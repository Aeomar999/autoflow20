Debugging is the product.

Everything below exists so the trace above can be true.

Immutable history

Runs remember the graph they ran

Each execution stores the graph as it was at trigger time. Editing a workflow never rewrites what last Tuesday looked like.

Crash-resumable

A restart resumes, it doesn’t replay

Every node runs as a durable step. If a worker dies mid-run, the run picks up at the last completed node — your customer isn’t charged twice.

Cost as a column

Tokens and dollars per node

Spend is recorded on the node execution, not mined out of logs later. Every budget alert and cost report is a sum over that column.

The node registry

One definition. Three consumers.

A node declares its config once, as a schema. The editor generates the form from it, the API validates saves against it, and the runtime executes against it. They cannot drift, so a workflow that passes the canvas linter cannot fail validation at run time.

Ship your own with the node SDK — a folder, not a fork.

export const definition = { type: "slack.send-message", category: "ACTION", label: "Send Slack message", configSchema: z.object({ channel: expr(z.string()) .describe("Channel or user id."), text: expr(z.string().multiline()), }), credentials: [{ key: "slack", type: "slack.oauth2", required: true }], defaultRetry: { maxAttempts: 3, backoffMs: 1000 }, }

Multi-model

Route by capability, not by contract.

Pick a model per node, or set a rule — cheapest capable, lowest latency, or an A/B bucket. Declare a fallback chain for when a provider has a bad afternoon.
